# Notification QA 시나리오 (task23)

## 1. 테스트 환경
- Android: Pixel 6a (Android 14)
- iOS: iPhone 13 (iOS 17.5)
- 앱 버전: 1.0.0-dev (task22 기반 빌드)
- 기본 설정: KST(UTC+9), 알림 권한 허용 후 진행

## 2. 공통 시나리오
각 시나리오는 아래 정보를 포함한다.
- 목적
- 준비 조건
- 수행 단계
- 기대 결과
- 실제 결과
- 비고/버그

## 3. 세부 시나리오

### 시나리오 A — 단일 알림 설정/취소
- **목적:** 정책 상세 화면에서 알림을 켜고 끄는 기본 흐름 검증.
- **준비 조건:** 알림 권한 허용, 정책 `policy-001` 존재.
- **수행 단계:**
  1) 정책 상세 → "알림 설정" → D-1 선택.
  2) 알림 목록 화면에서 항목 확인.
  3) 다시 상세 → 알림 해제.
- **기대 결과:** 알림이 예약되고 취소 시 목록에서 제거.
- **실제 결과:**
  - Android: ✅ 예약/취소 모두 정상.
  - iOS: ✅ 예약/취소 모두 정상.
- **비고/버그:** 없음.

### 시나리오 B — 멀티 알림(D-7 & D-1) 동시 예약
- **목적:** 동일 정책에 복수 알림 예약/취소 시 충돌 여부 확인.
- **준비 조건:** 정책 `policy-002` 존재.
- **수행 단계:**
  1) 상세 → "알림 설정" → D-7, D-1 모두 선택.
  2) 알림 목록에 두 건 모두 표시 확인.
  3) D-7만 해제 후 D-1 유지 확인.
- **기대 결과:** 선택한 옵션만 반영되고 취소한 항목은 사라짐.
- **실제 결과:**
  - Android: ✅ D-7 해제 후 D-1만 유지됨.
  - iOS: ✅ 동일 동작 확인.
- **비고/버그:** 없음.

### 시나리오 C — 앱 종료/재부팅 후 알림 유지
- **목적:** 로컬 스토리지와 스케줄링이 재시작 이후에도 지속되는지 확인.
- **준비 조건:** 정책 `policy-003`에 D-1 알림 설정.
- **수행 단계:**
  1) 앱 강제 종료.
  2) 기기 재부팅 후 앱 실행.
  3) 알림 목록과 실제 알림 발생 여부 확인.
- **기대 결과:** 알림이 유지되고 예정 시각에 발송.
- **실제 결과:**
  - Android: ✅ 목록/발송 정상.
  - iOS: ✅ 목록/발송 정상.
- **비고/버그:** 없음.

### 시나리오 D — 타임존 변경(KST → UTC)
- **목적:** 저장된 UTC 기반 시간이 로컬 타임존 변경 시 올바르게 재계산되는지 확인.
- **준비 조건:** 정책 `policy-004`에 D-1 알림 설정(설정 시각: KST 기준).
- **수행 단계:**
  1) 기기 타임존을 UTC로 변경.
  2) 알림 예정 시각과 발송 시각 확인.
- **기대 결과:** UTC 변환된 예약 시간이 새 타임존에서도 동일한 절대 시각으로 유지.
- **실제 결과:**
  - Android: ✅ 절대 시각 유지, 현지시각 표시만 변경.
  - iOS: ✅ 동일.
- **비고/버그:** 없음.

### 시나리오 E — 알림 탭 → 앱 진입
- **목적:** 알림 클릭 시 정책 상세로 이동하는지 검증.
- **준비 조건:** 정책 `policy-005`에 D-1 알림 설정, 앱 백그라운드 상태.
- **수행 단계:**
  1) 알림 도착 시 상단 배너/센터에서 탭.
  2) 앱 전환 후 라우팅 확인.
- **기대 결과:** 앱이 열리고 해당 정책 상세 화면으로 이동.
- **실제 결과:**
  - Android: ⚠️ 정책 상세 이동 실패(홈 화면에 머무름).
  - iOS: ✅ 상세 화면으로 정상 이동.
- **비고/버그:** Android에서 payload의 `policyId`를 해시 기반 notificationId로 역매핑하지 못해 취소/탭 라우팅이 불안정했음. `ReminderIdUtil.toNotificationId`로 통일하도록 수정함.

## 4. 발견 버그 및 조치
- **버그:** Android에서 hashCode 기반 notificationId가 앱 재시작 후 달라져 취소/탭 라우팅 실패.
- **조치:** Notification gateway에서 `ReminderIdUtil.toNotificationId`를 사용해 안정적인 정수 ID로 스케줄/취소하도록 수정.
- **추가 확인:** 변경 후 시나리오 E 재검증 시 정상 동작 확인.

## 5. 차후 과제
- 웹 빌드에 대한 알림 Fallback 동작 별도 정의 필요.
- 진입 라우트가 없는 오래된 알림(payload 누락) 보호 처리 추가 검토.
