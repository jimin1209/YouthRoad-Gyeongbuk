TASK 20 – 정책 메인 탭 구조 6개 → 3개로 축소 (UI/네비게이션만)

[목표]
- 현재 정책 메인 화면 상단(또는 BottomNavigation)에 존재하는
  "추천 / 전체 / 지역 / 검색 / 즐겨찾기 / 비교" 6개 탭 구조를
  "추천 / 탐색 / 보관함" 3개 탭 구조로 단순화한다.
- 이 TASK에서는 **enum/라벨/네비게이션/UI 탭 구조만 수정**하고,
  내부 비즈니스 로직(Provider, Repository, UseCase 등)은 변경하지 않는다.
- 나중에 Explore/Storage 화면 내부 구조를 리팩터링할 수 있도록
  "탐색 = 기존 전체 탭", "보관함 = 기존 즐겨찾기 탭"으로 임시 매핑만 수행한다.

────────────────────────────────────
[1. Scope (수정 범위)]
────────────────────────────────────
다음 파일들(또는 이와 동등한 역할의 파일)만 수정 대상으로 삼는다.

1) 정책 메인 탭/네비게이션 정의부
   - 예시: 
     - lib/navigation/app_router.dart
     - lib/navigation/app_bottom_nav.dart
     - lib/features/policy_new/presentation/policy_tab_screen.dart
   - "정책 메인 탭"을 정의하는 enum, TabBar/BottomNav 아이템 배열이 존재하는 파일.

2) 탭별 화면 라우팅/위젯 매핑
   - 예시:
     - lib/features/policy_new/presentation/screens/policy_home_screen.dart
     - 또는 정책 메인 탭에서 각 탭별로 보여줄 Screen을 결정하는 Widget/Router.

※ 주의: Policy 상세, 즐겨찾기 목록, 비교 화면의 내부 로직/위젯은 이 TASK에서 직접 수정하지 않는다.
※ 새로운 Screen(ExploreScreen/StorageScreen)을 지금 당장 새로 만들지 말고,
   기존 화면으로 "임시 매핑"만 한다. (2단계 TASK에서 새로 만들 예정)

────────────────────────────────────
[2. 현재 구조 파악 지시]
────────────────────────────────────
아래 순서로 현재 탭 구조와 enum을 파악하고, 그 결과에 맞게 리팩터링을 수행한다.

1) "정책 메인 탭" 용 enum/클래스를 찾는다.
   - 검색 키워드:
     - "PolicyTab"
     - "PolicyMainTab"
     - "policyTabs"
     - "추천", "전체", "지역", "검색", "즐겨찾기", "비교" 등 한글 라벨
   - 이 enum(또는 상수 집합)에는 현재 6개 탭이 정의되어 있을 것이다.
     (예: recommend, all, region, search, favorite, compare 등)

2) 탭 enum → 실제 화면 매핑 코드를 찾는다.
   - 예:
     - switch(tab) { case PolicyTab.recommend: return RecommendScreen(); ... }
     - 또는 BottomNavigationBarItem / TabBar 탭 리스트.

3) 이 enum과 매핑 코드를 기준으로 이후 변경 작업을 수행한다.

────────────────────────────────────
[3. enum 및 탭 리스트 변경]
────────────────────────────────────
1) 정책 메인 탭 enum/상수 정의를 다음 3개 값만 가지도록 변경한다.

   - 새로운 enum 예시:
     - recommend  // 추천
     - explore    // 탐색
     - storage    // 보관함

   - 기존 값 (all, region, search, favorite, compare 등)은
     - enum에서 제거하거나,
     - 더 이상 사용되지 않도록 Deprecation 주석을 남기고 실질적으로 사용을 중단한다.
     - 단, 이 TASK에서는 레거시 enum 값을 사용하는 기존 코드가 있다면
       컴파일 에러가 없도록 함께 정리할 것.

2) 탭/BottomNavigationBarItem 라벨 및 아이콘을 다음과 같이 수정한다.

   - 탭 1: 추천
     - label: "추천"
     - icon: 기존 추천 탭에서 사용하던 아이콘 재사용 (별/집 아이콘 등)

   - 탭 2: 탐색
     - label: "탐색"
     - icon: 기존 "전체" 또는 "검색" 탭에서 사용하던 리스트/돋보기 계열 아이콘 중 하나 재사용

   - 탭 3: 보관함
     - label: "보관함"
     - icon: 기존 "즐겨찾기" 또는 "비교" 탭에서 사용하던 북마크/폴더 계열 아이콘 중 하나 재사용

3) UI 상단/하단에서 실제로 보이는 탭은 항상 이 3개만 노출되도록 한다.
   - 기존 "전체 / 지역 / 검색 / 즐겨찾기 / 비교" 라벨이
     - TabBar, BottomNavigationBar, Drawer 등 어떤 UI에서도 더 이상 직접 노출되지 않도록 한다.

────────────────────────────────────
[4. 탭 → 화면 매핑 (임시 매핑)]
────────────────────────────────────
이 TASK에서는 내부 화면 리팩터링까지 하지 않고, 아래와 같이 "임시로" 기존 화면을 매핑한다.

1) 추천 탭 (recommend)
   - 기존 "추천" 탭에서 사용하던 화면/위젯 그대로 사용.
   - 예:
     - return PolicyRecommendScreen();
     - 또는 기존 RecommendTabView 위젯.

2) 탐색 탭 (explore)
   - 임시로 "기존 전체 탭 화면"을 사용한다.
   - 예:
     - return PolicyAllScreen();
   - 만약 화면명이 다르다면:
     - "전체 정책"을 보여주던 기존 탭의 Screen/Widget을 찾아서 연결한다.
   - 이 시점에서는 "지역/검색 통합"을 하지 않는다. (2단계에서 처리할 예정)

3) 보관함 탭 (storage)
   - 임시로 "기존 즐겨찾기 탭 화면"을 사용한다.
   - 예:
     - return PolicyFavoriteScreen();
   - 비교 화면(Compare)은:
     - 기존처럼 별도 라우트/버튼으로 진입 가능하도록 유지하되,
     - 상단 메인 탭에서 직접 "비교" 탭으로 진입하는 경로만 제거한다.

────────────────────────────────────
[5. 레거시 탭 라우트/코드 정리]
────────────────────────────────────
1) 기존 6개 탭 라우팅/매핑 코드에서
   - all / region / search / favorite / compare 에 해당하는 case 문이나 분기를 제거하거나,
   - 새로운 3개 탭 구조에 맞게 수정한다.

2) 사용되지 않는 라우트/화면은 지금 단계에서 삭제하지 말고,
   - 주석 또는 TODO로 "탐색/보관함 리팩터링 후 정리 예정"이라고 남긴다.
   - 예:
     - // TODO(TASK 20): ExploreScreen/StorageScreen 도입 후 legacy 탭 화면 정리

3) 정책 메인 탭을 사용하는 다른 코드(예: 상태 저장, deep link, 앱 재시작 시 마지막 탭 복원 등)가 있다면,
   - 새 enum 값(recommend/explore/storage) 기준으로 정상 동작하도록 최소한의 수정만 한다.

────────────────────────────────────
[6. Acceptance Criteria]
────────────────────────────────────
다음 조건을 모두 만족해야 한다.

1) 빌드 성공
   - flutter analyze / flutter build 기준으로 컴파일 에러가 없어야 한다.

2) UI 상단/하단 탭 표시
   - 정책 메인 화면에 진입했을 때,
     - "추천 / 탐색 / 보관함" 3개의 탭(또는 BottomNavigationBar 아이템)만 보일 것.
   - "전체 / 지역 / 검색 / 즐겨찾기 / 비교" 라벨은 더 이상 메인 탭에 보이지 않을 것.

3) 탭 동작
   - "추천" 탭: 기존 추천 탭 화면과 동일한 내용이 보일 것.
   - "탐색" 탭: 기존 "전체" 탭과 동일한 정책 리스트 화면이 보일 것.
   - "보관함" 탭: 기존 "즐겨찾기" 탭과 동일한 즐겨찾기 목록이 보일 것.

4) 비교 화면 접근성
   - 기존에 정책 카드에서 비교 화면으로 진입하던 플로우(버튼/아이콘)가 그대로 동작해야 한다.
   - 단, 상단/하단 메인 탭에서 직접 "비교" 탭으로 이동하는 UI는 제거되어야 한다.

5) 크래시/에러 로그
   - 탭 전환, 정책 상세 진입, 즐겨찾기/비교 기능 사용 시
     - 런타임 에러나 Riverpod/라우팅 관련 예외가 콘솔에 새로 생기지 않을 것.
